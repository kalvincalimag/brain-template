# Profile: software-project

## Use when

The brain tracks a software product or engineering project: its product intent, repositories, environments, team, and delivery history. The brain sits beside the code repositories. It is not one of them.

## Do not use when

The purpose is personal, financial, or administrative. Use `personal-admin` for those, or core only.

## What it adds

- `memory/product.md`, `memory/project.md`, `memory/team-onboarding.md`.
- `migrations/README.md`, for reviewed context transferred between tools or accounts.
- Rules in `AGENTS.md` for delivery and project sources.

## Interview

Ask these when creating the brain, and record the answers in the files named:

1. Which repositories and environments does this project have? (`memory/project.md`)
2. What is the authoritative source of product intent, such as a PRD? (`memory/product.md`, `memory/overview.md` under "Authority")
3. Who is on the team, and in what roles? (`memory/team-onboarding.md`)
4. Should writeback ever be pushed to a remote, and by which account? (`AGENTS.md` profile rules, only if the user says yes)
